# 01 要件定義 — スター・ウォーズ辞典アプリ

## 1. 目的

- スター・ウォーズ作品（映画・ドラマ・アニメ）に登場する **キャラクター・地名・用語** と、
  作中の出来事を並べた **年表** を、スマホでさっと引ける個人用の辞典を作る。
- 最大の特徴は **「視聴済み作品の範囲でしか情報が出ない」** こと。
  未視聴作品のネタバレを踏まずに、鑑賞中・鑑賞後に安心して調べられる。
- 公式サイト（starwars.disney.co.jp）にある「用語解説」「ヒストリー／時系列」の、
  **ネタバレ制御付き・個人用バージョン** というイメージ。

## 2. 利用者と利用シーン

- 利用者：作成者本人と家族。URL を知っていれば誰でも使えるが、ログインや端末間同期はしない。
- シーン：
  - Disney+ で視聴中・視聴後に「この人誰だっけ」「この星どこ」「この出来事いつ」を調べる。
  - 家族それぞれが自分のスマホで自分の視聴状況を設定する（設定は端末ごとに独立）。
  - 新しいシーズンを見終わったら設定にチェックを入れ、新しく読めるようになった項目を眺める。

## 3. 前提・決定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| 形態 | PWA（Vite + React + TypeScript） | ストア審査不要、iPhone/Android 両対応、既存の自作アプリと同じ配信方法 |
| 配信 | GitHub Pages | 既存アプリと同じ運用。更新 = push |
| データ | リポジトリ内の JSON（`data/`） | サーバー不要。新作対応は JSON を足して push するだけ |
| 端末内保存 | localStorage | 視聴済み作品・設定・閲覧履歴。サーバーに送らない |
| 画像 | 扱わない | 権利面と容量。文字情報に集中する |
| 言語 | 日本語 UI / 日本語データ。検索用に英語名と読みを持つ | 公式日本語表記（Disney+ の字幕・公式サイト）に合わせる |
| 利用目的 | 個人・家族の非営利利用 | 権利面の注意は 05 参照 |

## 4. 用語の定義（ドキュメント全体で統一）

| 用語 | 英語（コード上の名前） | 意味 |
|---|---|---|
| 作品 | work | 視聴済みを選ぶ最小単位。映画 1 本、またはドラマ・アニメの 1 シーズン |
| シリーズ | series | 複数シーズンをまとめる単位（例：マンダロリアン S1〜S3＋映画） |
| 項目 | entity | 辞典の見出し 1 つ。人物・場所・組織・種族・乗り物・道具・用語・出来事のいずれか |
| 記述 | fact | 項目の説明文 1 つ（1〜2 文）。それぞれ「どの作品で明かされるか」を持つ |
| 名前 | name | 項目の表示名。主名称 1 つ＋別名（明かされる作品つき） |
| 同一人物 | sameAs | 別々の項目として登録した 2 つが、ある作品を見ると同一だと分かる関係 |
| 視聴済み集合 | watched | その端末で「視聴済み」にチェックされた作品 ID の集合 |
| 解放 | unlock | 項目・記述・名前が watched によって表示可能になること |
| パック | pack | 作品 1 つ分のデータの束（`data/packs/<work-id>/`）。新作対応はパック追加で行う |

## 5. 機能要件

優先度：**MUST**（これがないと成立しない） / **SHOULD**（初版に入れたい） / **COULD**（余裕があれば）

### F-01 視聴済み作品の設定（MUST）
- 設定画面で作品にチェックを入れる。シリーズ単位の「全シーズン」一括チェックも可能。
- 「映画 9 作をまとめて」「すべて視聴済み（ネタバレ全開放）」「すべて解除」のクイック操作。
- 設定は端末の localStorage に保存し、再起動・オフラインでも保持される。
- まだデータパックが作られていない作品には「データ準備中」と表示する（チェック自体は可能で、記憶される）。
- 初回起動時（何も設定がない）はホーム画面から設定へ誘導する。

### F-02 辞典（MUST）
- 一覧：種類（人物／場所／組織／種族／乗り物・兵器／道具／用語／出来事）ごとに、五十音順で表示。
- 検索：名前・別名・読み・英語名で部分一致。ひらがな／カタカナ、「・」「＝」の有無、大文字小文字の違いを吸収する。
- 詳細：表示名、別名、種類、記述の一覧、登場作品（**視聴済みのものだけ**）、関連項目、（出来事なら）年代。
- 一覧・検索・関連項目・件数など、画面に出るものはすべて watched でフィルタされる（02 参照）。

### F-03 年表（MUST）
- 出来事（type: event）を年代順に縦に並べる。年代は「ヤヴィンの戦い」を 0 年とする BBY/ABY 表記＋日本語の補足。
- 時代区分（eras.json）を見出しとして表示する。時代区分も watched で解放制御する。
- 出来事をタップすると項目詳細に飛ぶ。
- 視聴済み作品が作中年代のどこに位置するかを帯で示す（未視聴作品は出さない）。

### F-04 本文内リンクと「戻る」（MUST）
- 記述の本文中に出てくる項目名はリンクになっていて、タップすると飛べる。
- 戻るボタン（画面上部）と、Android の戻る操作で前の画面に戻れる。スクロール位置も復元する。
- リンク先が未解放（まだ見てはいけない項目）なら、リンクにせず文字だけを表示する。
- 直前に見た項目を数件、画面上部に「足あと」として表示し、タップで戻れる（SHOULD）。

### F-05 ネタバレ制御（MUST）
- 02_data_model.md の規則に従う。要点：
  - 項目は「登場作品のどれか 1 つでも視聴済み」なら解放。
  - 記述は「明かされる作品のどれか 1 つでも視聴済み」なら表示（**OR 条件**。公開順・時系列順どちらで見ても正しく動く）。
  - 別名・同一人物リンクも同じ仕組みで制御。
- 判定ロジックは 1 か所に集約し、ユニットテストで §8 のシナリオを保証する。

### F-06 新着通知（SHOULD）
- 設定を変更して新しく解放された項目・記述があれば、「新しく読めるようになった項目（N 件）」の画面を出す。
- 一覧では NEW バッジを付け、開いたら消える。

### F-07 データ追加・更新（MUST）
- 新作が出たら `data/packs/<work-id>/` を追加し、既存項目へ記述を追記するだけで対応できる。
- `npm run data:validate` でリンク切れ・ネタバレ漏れの可能性・必須項目の欠落を検出する。
- データにはバージョン番号があり、設定画面で確認できる。更新履歴（CHANGELOG）もアプリ内で読める。
- アプリ更新時はサービスワーカーが新版を取得し、「更新があります」と案内して再読み込みできる（SHOULD）。

### F-08 PWA（MUST）
- ホーム画面に追加でき、スタンドアロン（ブラウザの枠なし）で起動する。
- オフラインで全機能が動く（データも含めてキャッシュ）。
- アイコンはユーザー自作のものを使う（仕様は 03 参照）。差し替えまでは仮アイコン。

### F-09 設定の書き出し・取り込み（COULD）
- 視聴済み設定を JSON テキストとしてコピー／貼り付けで移行できる（機種変更・家族への共有用）。

### F-10 お気に入り・閲覧履歴・メモ（COULD）
- 項目をお気に入り登録、閲覧履歴の一覧、項目ごとの自分用メモ（すべて端末内保存）。

### F-11 作品一覧（SHOULD）
- 視聴済み作品を「公開順」「作中時系列順」で並べて見られる画面。未視聴作品は出さない。

## 6. 非機能要件

- **速度**：項目 2,000 件・記述 10,000 件程度でも検索が体感即時（クライアント側インデックス）。
- **オフライン**：機内モードでも起動・検索・閲覧できる。
- **文字サイズ**：小／中／大を設定で切替。最小タップ領域 44px。
- **コントラスト**：黒背景・白文字が基本。本文リンクは色＋下線で区別する。
- **データ量**：db.json は 2〜3 MB 以内を目安（超えたら分割を検討）。
- **対応環境**：iOS Safari（ホーム画面追加）、Android Chrome。PC ブラウザでも崩れない。
- **プライバシー**：外部送信ゼロ。解析・広告・外部フォントの読み込み可否も設定で選べるとなおよい（self-host 推奨）。

## 7. スコープ外（やらないこと）

- ユーザー登録、クラウド同期、複数端末の設定共有（F-09 の手動コピーで代替）
- 画像・動画・音声の収録
- 他言語 UI
- 公式データベースとの連携、自動収集
- コメント・投稿などの共有機能
- アプリストアへの公開（必要になったら Capacitor で包む。データ設計は変えない）
