# 05 コンテンツ執筆ガイド — 作品パックの作り方

データはアプリの価値そのもの。ここでは **何を・どう書くか** と **新作を追加する手順** を決める。
Claude Code に下書きを作らせ、人間が確認して確定する、という流れを前提にしている。

## 1. 新作（または未対応作品）を追加する手順

1. **作品マスタを確認**：`data/works.json` にその作品があるか。なければ 02 §3 の形式で追加（ID は既存の命名に合わせる）。
2. **候補出し**：その作品に登場・言及する「人物／場所／組織／種族／乗り物・兵器／道具／用語／出来事」を列挙する。
   主要なものから。脇役や一度しか出ない地名は後回しでよい（あとから足せる）。
3. **パックを書く**：`data/packs/<work-id>/entities.json`。
   - 新規項目は `type` と `names` を含めて定義する。
   - 既存項目への追記は `id` と `facts`（必要なら `appearsIn` / `sameAs` / 別名）だけ。
4. **既存記述の見直し（重要）**：この作品で明かされる事実が、すでに別のパックに書かれていないか探す。
   あれば、その記述の `revealedBy` に `<work-id>` を **足す**（置き換えない）。
   - 例：エピソード 3 のパックを作るとき、ep5 パックの「ルークの父」や `sameAs` に `"ep3"` を足す。
   - 探し方：登場人物の ID で `data/packs` を grep し、各記述を「この作品を見た人も知っているか？」で判定する。
5. **検証**：`npm run data:validate` → エラー 0。警告 W01 は「将来のパックで対処」なので内容だけ把握。
6. **見え方の確認**：`npm run data:preview -- --watched <work-id>`（その作品だけ見た人の見え方）と、
   自分の実際の視聴状況での見え方を確認。
7. **`needsCheck` を潰す**：下書きで `needsCheck: true` が付いた記述を自分で確認し、直して外す。
8. **バージョンと履歴**：`data/meta.json` の `dataVersion` を上げ（パック追加は 0.1.0 → 0.2.0、記述の修正だけなら 0.2.0 → 0.2.1）、
   `data/CHANGELOG.md` に 1〜3 行。
9. コミット → push → スマホで「更新があります」→ 設定で視聴済みにチェック → 新着を見る。

## 2. 記述（fact）の書き方

### 基本
- **1 記述 = 1〜2 文、1 つの事実**。長い説明は記述を分ける（分けるほど、明かされる作品を細かく付けられる）。
- **客観的に、常体（〜である／〜した）**。感想・評価・解釈は書かない。
- **その作品を見終わった人が知っていること** だけを書く。予告編・公式サイト・ファンの通説・後の作品の情報は混ぜない。
- 最初の 1 記述は `kind: "summary"` にして「一言でいうと誰／何か」を書く（項目に 1 つ、最初に定義するパックで）。
- 作品名を本文に書かない（「エピソード 5 で〜」は不要。出典は `revealedBy` が担い、アプリが略称ラベルを出す）。
- 現実世界の情報（俳優、公開年、制作裏話）は書かない。

### ネタバレの段階分け（最重要）
同じ人物でも、知ってよいことは作品ごとに増える。**作品ごとに記述を分け、`revealedBy` を正確に付ける**。

```
ダース・ベイダー
  [ep4] 黒い甲冑と仮面の帝国の実力者。ダークサイドを使う。
  [ep4] かつてオビ＝ワンの弟子だった。
  [ep5, ep3] ルーク・スカイウォーカーの実の父である。
  [ep6, ep3] 本名はアナキン・スカイウォーカー …… ← これは別名ではなく sameAs で表現する（02 §6）
```

判定のチェックリスト：
- この文を、**その作品しか見ていない人** が読んで驚きが減らないか？ 減るなら `revealedBy` が間違っている。
- 公開順ではなく **時系列順** で見ている人のことも考える（エピソード 1〜3 → 4 の順で見た人に、4 の時点で何が自明か）。
- 「この人は後で裏切る」「この星は後で破壊される」など **未来の出来事** は、それが起きる作品の `revealedBy` にする。
- 名前そのものがネタバレの関係（正体・血縁・変名）は `sameAs` か、`revealedBy` 付きの別名で。迷ったら別項目＋`sameAs`。
- 作中で「〜と語られた」情報（オビ＝ワンがルークに話した父の最期など）は、語られた通りに書く。後の作品で覆る場合は、
  覆す記述を後の作品の `revealedBy` で **追加** する（元の記述は消さない。歴史が残るほうが辞典として面白い）。

### リンクの付け方
- 本文中の項目名は `[[id]]` でリンク。1 つの記述の中で同じ項目へのリンクは 1 回まで。
- 表示名と違う言い方をしたいとき、または **リンク先がその作品で未解放になり得るとき** は `[[id|ラベル]]`。
- 主語の項目自身にはリンクしない（ベイダーの記述の中でベイダーにリンクしない）。
- リンクを張った相手は、その作品に登場・言及しているはず。validate の E08/W01 が出たら、相手の項目にその作品の記述を足すか、ラベル付きにする。

### 名前の表記
- **公式日本語表記**（Disney+ 字幕・公式サイト）に合わせる。例：`オビ＝ワン・ケノービ`（＝は全角）、`クワイ＝ガン・ジン`、`R2-D2`（半角英数とハイフン）、`C-3PO`。
- 人名の中黒は全角「・」。長音は「ー」。
- `reading` はひらがな＋中黒（例：`おびわん・けのーび`）。英数字はそのまま（例：`R2-D2` → `あーるつーでぃーつー`）。
- `en` は英語の正式表記。
- 称号は別名に `kind: "title"`（例：「レイア姫」「皇帝」）、愛称は `kind: "nickname"`（「チューイ」）。

### 年代（出来事）
- `year` はヤヴィンの戦い基準（BBY 負 / ABY 正）。作品の `timeline` と矛盾しないようにする。
- 正確な年が不明なら `precision: "approx"` と `order` で並び順だけ決める。
- 出来事名は「○○の戦い」「○○の建国」「○○の陥落」のように名詞句で。

## 3. Claude Code に下書きさせるときの約束

- 下書きプロンプトは `docs/04_dev_plan.md` Phase 8 のもの。候補一覧 → 承認 → 執筆 → 既存見直し → 検証 の順を崩さない。
- Claude Code は作品の細部を **間違えることがある**（人名の表記、年、出来事の順序、誰が何を言ったか）。
  自信のない記述には `needsCheck: true` を付けさせ、人間が確認してから外す。
- 1 回のプロンプトで 1 作品。1 作品が大きい（クローン・ウォーズの 1 シーズンなど）ときは「人物だけ」「場所と組織だけ」に分ける。
- 既存項目の主名称・`type`・ID を Claude Code に変えさせない（変える場合は人間が決める）。
- 候補出しのとき、Claude Code に「視聴済みにすべき前提作品」を出させない。ネタバレ判定は上のチェックリストでこちらが行う。

## 4. 権利面の注意（個人・家族利用でも守る）

これは法的助言ではなく、トラブルを避けるための運用ルール。

- **文章は自分（または Claude Code）の言葉で書く。** 公式サイト・パンフレット・書籍・字幕の文章をコピーしない。
- **Wookieepedia などのファンサイトも文章コピーはしない。** 事実関係の確認に使うのはよい。
  もし引用・翻訳を一部でも使うなら、そのサイトのライセンス（Wookieepedia は CC BY-SA）に従い、about 画面に出典とライセンスを明記する。
- **公式画像・公式ロゴ・公式フォント風のロゴは使わない。** アプリ内のコンテンツ（項目・年表・本文）には画像を一切置かない。
- **ホーム画面用アイコンだけは例外。** 作中キャラクターを思わせるシルエット画像を使っている（`assets/icon-source.png`。
  `npm run icons` で各サイズを生成）。公式ロゴ・公式画像・公式フォント風ロゴを使わないことと、
  下の「個人・家族利用にとどめる」条件（配布・収益化・不特定多数への公開をしない）を守ることが前提。
  第三者に配る必要が出たときは自作図案に差し替える。
- アプリ名・about 画面に「非公式のファン制作・個人利用」であることを書く。「公式」「Official」「Disney」「Lucasfilm」を名乗らない。
- 公開 URL を不特定多数に宣伝しない（家族・知人の範囲）。配布や収益化はしない。

## 5. 用字用語（スタイルシート）

| 項目 | ルール |
|---|---|
| 文体 | 常体（である調）。体言止めは summary のみ可 |
| 数字 | 半角。数字と助数詞の間にスペースは入れない（「2つの太陽」「800年」） |
| 記号 | 中黒・イコール・括弧は全角。英数字と `-` は半角 |
| 作品の略称（出典ラベル） | works.json の `id` をアプリ側で略称に変換する（例：ep4 → `EP4`、mando-s2 → `マンダロリアン S2`） |
| 年 | 本文には「ヤヴィンの戦いの3年後」のような相対表現を使い、BBY/ABY の数値は `date` に持たせる |
| 敬称 | なし |
| 種族名 | カタカナ（ウーキー、トワイレック） |
| 「銀河」 | 「銀河」のみ。「銀河系」は使わない |

## 6. 最初に作るパックの順番（提案）

自分が **視聴済みの作品** を公開順に。見ていない作品のパックは、見るまで作らない（作ると自分がネタバレを踏む）。
サンプルの ep4 / ep5 は見本なので、本番ではそのまま使っても、作り直してもよい。

目安の分量：映画 1 本で 30〜60 項目・100〜200 記述。ドラマ 1 シーズンで 20〜40 項目。
最初から完璧を目指さず、「人物と場所の主要どころ＋年表の出来事 5 個」で 1 周し、足りないと感じたら増やす。
